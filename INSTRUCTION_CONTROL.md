# Принятые инструкции форка

Основные инструкции и каталог моделей становятся частью явно принятого снимка.
Обычный процесс Codex читает его из защищённого каталога Windows. Новый источник
или изменённая инструкция требуют подготовки кандидата, просмотра и принятия
отдельным процессом с UAC. Серверные отказы эта схема не изменяет.

## Настройки снимка

```json
{
  "instructions": {"updates": "manual", "resume": "rebuild"},
  "controls": {
    "dangerous_commands": "confirm",
    "managed_requirements": "local-only",
    "hooks": "approved-only"
  },
  "git_attribution": {"commit_trailer": "", "pr_footer": ""}
}
```

`dangerous_commands` управляет эвристикой для команд без подходящего явного
правила: `confirm` запрашивает подтверждение, `warn` показывает предупреждение,
`block` запрещает, `off` выключает влияние этой эвристики на решение. При
`confirm` и `approval_policy=never` команда запрещается. Явные правила, ограничения
среды и sandbox применяются отдельно во всех четырёх режимах. `off` не выдаёт
права администратора и не отключает серверные отказы.

`managed_requirements` принимает `local-only` или `approved-sources`. Изменение
управляемого источника не считается автоматическим разрешением применить его.
Требования к аутентификации и принятые ограничения сохраняют собственную семантику.

`hooks` принимает `approved-only` или `off`. Одобрение относится к декларации
hook и принятым файлам пакета. Обязательный управляемый hook нельзя молча
пропустить настройкой `off`.

Пустые `commit_trailer` и `pr_footer` не добавляют атрибуцию. Contributor,
получавший политику Git-атрибуции через backend, удалён.

## Подготовка и применение

Полная схема хранилища, список семи EXE, UAC и ACL описаны в
[instruction-control/README.md](codex-rs/instruction-control/README.md).

```powershell
.\codex-policy-manager.exe prepare --main .\main.md --catalog .\models.json --output .\candidate.json
.\codex.exe instructions capture --candidate .\candidate.json --output .\candidate-captured.json --cwd C:\project
.\codex-policy-manager.exe inspect --candidate .\candidate-captured.json
.\codex-policy-manager.exe install --distribution . --candidate .\candidate-captured.json
```

`capture` собирает текущие AGENTS.md, skills с метаданными и файлами пакетов,
hooks, отрисованные инструкции и схемы инструментов. Он не генерирует ответ
модели и не принимает настройки. Необнаруженные заранее инструменты требуют
отдельного принятия при первом использовании. Подготовка кандидата с источниками
MCP может обращаться к настроенным MCP-серверам для обнаружения инструментов.
Реестр `capture` пока собирается с extensions skills и attribution; полный
реестр extensions рабочего app-server он не воспроизводит. Поэтому даже после
`capture` некоторые схемы, включая MCP и code-mode, могут потребовать отдельного
просмотра и принятия при первом использовании.
Шаг `capture` обязателен: он добавляет настройки выбора инструкций. Минимальный
кандидат после одного `prepare` ещё не содержит этих настроек. Сбор файлов
ограничен 8192 файлами и 24 MiB; reparse points и возможные файлы с учётными
данными отклоняются, частичный пакет автоматически не принимается.
Для явного добавления управляемых облачных источников есть `capture --include-cloud`.
Проверка наличия управляемой конфигурации может обращаться к серверу и обновлять
её кэш; непринятый текст при этом не применяется. Поддерживается один локальный
источник `requirements.toml`; неоднозначный порядок нескольких источников
завершается ошибкой.

Проектные AGENTS.md привязаны к идентификатору среды исполнения и рабочей
директории. Автоматический сбор реализован для локальной среды; источники
удалённой среды пока импортируются явно с её идентификатором. Совпадение пути
между локальным и удалённым executor не переносит принятие между ними.

Для последующих изменений используется `apply --candidate ...`, затем перезапуск
Codex. Запущенный процесс сохраняет первоначально принятый снимок. Команда
установленного менеджера `verify` проверяет хеши, ACL и отказ Windows выдать
обычному процессу доступ на изменение защищённого состояния, не изменяя файлы.

Установка не заменяет пользовательский `.codex`: там остаются сессии,
аутентификация и обычные настройки. Запускать нужно установленный защищённый EXE.
Изменённый EXE из пользовательского checkout не признаётся защищённым клиентом.

## Resume и compaction

Основной промпт выбирается из принятого состояния, старый промпт из сохранённой
сессии его не заменяет. Текущие служебные инструкции строятся заново. Сообщения
пользователя, ответы и результаты инструментов сохраняются.

Compaction помечается отпечатком эффективного контекста: принятой версии,
модели и её сообщений, режима, рабочей директории, разрешений и источников.
Несовместимая compaction не используется как достоверный новый контекст:
восстанавливается исходная история из архива. Если исходных данных нет или
старый формат неоднозначен, возвращается явная ошибка миграции. Исходный архив
при этом не переписывается.

## Повторный аудит: оставшиеся границы

| Источник или механизм | Поведение |
|---|---|
| Основной промпт и каталог | Принятые копии; обычное обновление каталога не заменяет их |
| Глобальные и проектные AGENTS.md | Принятый текст; новые и изменённые файлы автоматически не подхватываются |
| Skills | Принятые документы, метаданные и копии файлов; ограниченный сбор пакета завершается ошибкой, если копия неполная |
| Hooks | Проверка принятой декларации; исполнение hook остаётся отдельной явно включаемой возможностью |
| Описания и схемы инструментов | Проверка перед передачей модели, включая отложенный поиск инструментов |
| История | Хранится, но старые служебные инструкции не становятся новым принятым состоянием |
| Выбор инструкций | Бюджет и видимость AGENTS.md и skills, шаблоны compaction/realtime и служебные подсказки фиксируются в снимке |
| Локальная cyber-ветка для prefix rules | Исключение по модели удалено; одинаковые правила применяются ко всем моделям |
| Guardian | Классификатор и запросы автоматическому reviewer удалены; маршрутизация ручных подтверждений и совместимые типы истории ещё содержат это имя. Требование обязательного AutoReview возвращает ошибку недоступности |
| Серверные ошибки `cyber_policy` и отказы | Обработка сохранена; автоматического обхода или повторной отправки для обхода нет |
| Approval и sandbox | Сохранены; это отдельные операционные ограничения |
| Текущее время, разрешения и другие факты среды | Меняются в ходе работы; они не являются автоматическим обновлением основного промпта |
| Результаты инструментов, веб-страницы, сообщения других агентов | Динамические данные; защита снимка не гарантирует отсутствия prompt injection в этих данных |

Защищённый TUI использует встроенный backend. Автоматическое подключение к
существующему daemon отключено: тот может оказаться старой сборкой. Удалённое
подключение и `queue` в защищённом режиме завершаются явной ошибкой, пока нет
проверки происхождения backend. Обычный local coding, subagents и прямой запуск
`app-server` сохраняются. Эти ограничения не следует скрывать за утверждением,
что все способы подключения полностью совместимы.
Публичный upstream updater в защищённом режиме не используется; автоматическая
проверка его новых версий в TUI отключена. Изменение бинарников форка требует
отдельно проверенного дистрибутива.

Отпечаток compaction в пользовательской истории проверяет согласованность и не
является подписью от подмены самой истории. История остаётся пользовательскими
данными. Текст ответа, вывода инструмента или summary может повторять инструкции;
защита основного промпта не означает удаления всех таких фраз из данных задачи.

Защищается принятое состояние инструкций и файлов пакетов. Это не изоляция всех
запускаемых программ: абсолютный путь к внешнему скрипту в тексте skill, внешний
EXE hook, данные плагина и ответы MCP могут оставаться изменяемыми. Не следует
приравнивать защиту снимка к неизменности всего окружения.

Удаление принятого непустого источника hooks из обнаружения вызывает явную ошибку:
нужно восстановить декларацию либо собрать и принять кандидат с её удалением.
Эта проверка консервативна: смена workspace, где прежний hook недоступен, тоже
может потребовать нового принятия. Операционный `hook state.enabled=false`
сохраняется и диагностируется отдельно; принятие декларации не включает hook заново.

Переключатели активации plugins фиксируются, но удаление установки плагина или
недоступность его MCP/apps может убрать условные подсказки о возможностях плагина.
Проверка блокирует изменённую передаваемую инструкцию, но не требует присутствия
каждой когда-либо принятой подсказки `plugins.instructions` в каждом запросе:
такие подсказки зависят от явного выбора плагина пользователем и доступных возможностей.

SHA-256 обнаруживает изменение; границу прав создаёт ACL Windows и отдельный
повышенный процесс. Сценарий, где сам Codex запущен администратором, в эту
гарантию не входит. `install` пока предназначен для первой установки; замена
уже установленных бинарников отдельным процессом обновления не реализована.
Одновременные `apply` сериализуются блокировкой защищённого файла; второй
менеджер получает явную ошибку занятости. Прерванная первая установка может
оставить неполный защищённый каталог; автоматическое восстановление или откат
такой установки пока не реализованы. Реальные клики UAC и окна принятия ещё
предстоит проверить на готовом дистрибутиве.
